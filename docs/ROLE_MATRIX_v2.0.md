# 👥 角色权限矩阵（V2.0）

## `MyShop 无头电商 · agri-ecommerce`

> **版本**：V2.0（与《功能规格及技术架构说明书》V1.0、《API 接口契约》V2.3 对齐）
> **适用阶段**：二期（虚拟购物卡、积分中心、代理商仪表盘全面上线）
> **目标**：明确定义各类用户可访问的数据域与 API 操作，建立“最小权限 + 可审计”基线

------

## 一、角色定义与识别

| 角色                         | WordPress 基础角色    | 身份判定标记                                                                  | 主要职责与能力                                     |
| ---------------------------- | --------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------- |
| **访客（Guest）**            | 未登录                 | 无 Token                                                                      | 浏览公开内容，承接邀请或购物卡领取入口             |
| **认证买家（Customer）**     | `customer`             | 成功登录（JWT Token）                                                         | 下单、上传凭证、查看个人资产（订单/购物卡/积分）   |
| **分销推广人（Referrer）**   | `customer`             | `usermeta.myshop_referral_code` 存在                                          | 拥有邀请码，查看邀请数据与佣金明细                 |
| **购物卡持有人（Card Owner）** | `customer`             | `wp_myshop_gift_cards.purchaser_id` 或 `redeemer_id` 关联当前用户              | 管理购物卡、赠礼、领取、重置 PIN                    |
| **代理商（Agent）**          | `shop_manager`         | `usermeta.myshop_agent_status = approved`                                     | 查看团队指标、下级代理、佣金、渠道素材             |
| **运营管理员（Admin）**      | `administrator`        | 后台帐号；小程序不暴露 Token                                                  | 配置商品/活动、审核订单、人工处理交易              |

> ✅ 认证买家可同时具备推广人、持卡人或代理商身份；权限取并集并以最小授权策略计算。

## 三、数据可见性与隔离策略

| 数据域           | 认证买家默认范围                                   | 分销推广人/购物卡持有人扩展                           | 代理商扩展                                   |
| ---------------- | -------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------- |
| 订单（含凭证）   | 仅本人订单；图片路径加签，链接 10 分钟内有效        | 同上                                                  | 同上                                         |
| 购物卡资产       | 购卡人：订单关联卡；受赠人：已领取卡；共享日志仅本人 | 可额外查看分享口令状态、核销日志                      | 无额外权限                                   |
| 积分流水         | 仅本人明细，分页查询，数据导出需后台操作            | 同上                                                  | 同上                                         |
| 推广大数据       | —                                                  | 查看直接/间接邀请数据（隐藏手机号，展示脱敏昵称）     | 可查看团队下所有邀请数据（脱敏处理）         |
| 佣金报表         | —                                                  | 自身推广佣金、提现记录                                | 自身 + 团队佣金走势（成员信息脱敏）          |
| 代理仪表盘指标   | —                                                  | —                                                      | 可见团队 GMV、活跃代理数、任务完成率         |

> 🔒 任何跨用户检索必须在数据库层面添加 `WHERE owner_id = current_user_id` 或授权校验，禁止在前端过滤。

## 四、授权校验流程

1. **统一认证**：所有受保护接口使用 JWT；Token 失效时后端返回 401，前端清除本地缓存并跳转登录。
2. **角色识别**：
     - 分销人：`myshop_referral_code` 存在且 `referral_status = active`。
     - 购物卡持有人：卡记录中的 `purchaser_id` / `redeemer_id` 匹配当前用户。
     - 代理商：`myshop_agent_status = approved`，未通过审核返回 403。
3. **领域校验示例**：
```php
// 购物卡分享：仅购卡人可生成口令
if ((int) $card->purchaser_id !== get_current_user_id()) {
        return new WP_Error('FORBIDDEN', '无权操作该购物卡', [ 'status' => 403 ]);
}

// 代理下级列表：确保代理身份
if (!myshop_is_agent($current_user_id)) {
        return new WP_Error('FORBIDDEN', '当前账号非代理商', [ 'status' => 403 ]);
}
```

4. **分享口令安全**：
     - `/gift-cards/{id}/share` 生成一次性 token，写入 `wp_myshop_gift_card_share_logs`；成功领取或撤销后立即失效。
     - `/gift-cards/claim` 必须登录，并校验手机号与 token 匹配，成功后记录领取人。
5. **积分预占**：`/points/redeem` 执行时检查用户积分余额 & 预占状态，失败次数达到策略阈值触发风控提醒。

------

## 五、审计与风控

- **操作日志**：
    - 购物卡：分享、领取、重置 PIN、核销均记录于 `wp_myshop_gift_card_share_logs` / `wp_myshop_gift_card_redemptions`。
    - 代理商：变更等级、冻结账号写入 `wp_myshop_agent_audit_logs`。
- **异常场景**：
    - 连续 3 次积分兑换失败 → 返回错误码 `POINTS_REDEEM_QUOTA_EXCEEDED`，前端提示联系人工客服。
    - 礼品卡口令输入错误超阈值 → 锁定卡片（`status=locked`），需走客服解锁流程。
- **最小权限落实**：页面级别根据用户角色动态显示入口，避免产生多余的 API 请求；后端仍做硬性校验。

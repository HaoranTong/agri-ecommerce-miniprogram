## 二、Postman接口测试指南

### 2.1 测试环境配置

**环境文件位置**: `docs/postman/MyShop_Dev.postman_environment.json`

**必需配置项**:
```json
{
  "BASE_URL": "https://agri-ecommerce.test",
  "API_PREFIX": "/wp-json/myshop/v1",
  "AUTH_TOKEN": "{{token}}"
}
```

### 2.2 核心测试流程

#### 步骤1: 认证测试
```bash
# 1. 获取微信登录code（开发工具中获取）
# 2. 调用登录接口
POST /auth/login
{
  "code": "test_code_here"
}

# 预期结果: 返回token和用户信息
# 状态码: 200
# 响应包含: token, user_id, openid
```

#### 步骤2: 业务功能测试
```bash
# 商品相关
GET /products                    # 获取商品列表
GET /products/redeem           # 获取积分兑换商品

# 订单相关  
POST /orders                   # 创建订单
GET /orders                    # 获取订单列表
POST /orders/{id}/upload-proof # 上传支付凭证

# 购物卡相关
GET /gift-cards                # 获取我的购物卡
POST /gift-cards/share         # 分享购物卡
POST /gift-cards/redeem        # 兑换购物卡

# 积分相关
GET /points/balance           # 获取积分余额
GET /points/ledger            # 获取积分流水
POST /points/spend            # 使用积分

# 代理相关
POST /agents/apply            # 申请代理
GET /agents/me               # 获取代理信息

# 分销相关
GET /invitations/summary      # 邀请统计
POST /invitations/track       # 渠道追踪
GET /analytics/channel        # 渠道分析
```

### 2.3 关键测试用例

#### 高优先级测试用例
1. **用户认证流程**
   - 正常登录 → 获取token → 访问受保护接口
   - 无效token → 401错误 → 跳转到登录页

2. **订单创建流程**
   - 创建普通订单 → 检查订单状态
   - 创建积分抵扣订单 → 验证积分扣减
   - 创建购物卡订单 → 验证购物卡生成

3. **支付流程测试**
   - 上传支付凭证 → 检查状态变更
   - 使用优惠券 → 验证金额计算
   - 使用购物卡 → 验证余额扣减

4. **购物卡功能测试**
   - 购买储值卡 → 检查卡号生成
   - 分享购物卡 → 检查分享链接
   - 兑换商品 → 检查0元订单

5. **积分系统测试**
   - 获取积分 → 检查余额显示
   - 积分流水 → 检查明细记录
   - 积分兑换 → 检查商品兑换

#### 自动化测试命令
```bash

npm install -g newman

  -e docs/postman/MyShop_Dev.postman_environment.json \

  --reporter-junit-export test-results.xml

# 仅运行关键接口测试

  -e docs/postman/MyShop_Dev.postman_environment.json \
```

## 五、自动化测试配置

### 5.1 Jest单元测试配置

**配置文件**: `jest.config.js`
```javascript
module.exports = {
  testEnvironment: 'node',
  testMatch: ['**/src/**/__tests__/**/*.test.{js,ts,tsx}'],
  collectCoverageFrom: [
    'src/**/*.{js,ts,tsx}',
    '!src/**/*.d.ts',
    '!src/**/__tests__/**/*'
  ],
  coverageDirectory: 'coverage',
  coverageReporters: ['text', 'lcov', 'html']
};
```

**测试命令**:
```bash
# 运行所有测试
npm test

# 运行测试并生成覆盖率报告
npm run test:coverage

# 监视模式运行测试
npm run test:watch
```

### 5.2 CI/CD集成

**GitHub Actions配置**: `.github/workflows/test.yml`
```yaml
name: Test Suite
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      - name: Install dependencies
        run: npm install
      - name: Run unit tests
        run: npm test
      - name: Run API tests
        run: npm run test:api
      - name: Upload coverage
        uses: codecov/codecov-action@v3
```

# 微信开发者工具多账户测试指南

## 方法一：使用真机调试（推荐）

### 步骤1：准备两部手机
1. 手机A：登录账号A（购买购物卡的用户）
2. 手机B：登录账号B（领取购物卡的用户）

### 步骤2：开启真机调试
1. 在微信开发者工具中，点击工具栏的"预览"按钮
2. 选择"真机调试"
3. 用手机A扫描二维码，进入小程序
4. 在手机A上完成购买和分享操作

### 步骤3：分享给手机B
1. 在手机A上完成购物卡分享，生成二维码图片
2. 将二维码图片发送给手机B（通过微信、邮件等方式）
3. 手机B长按识别二维码或使用微信扫一扫
4. 手机B登录账号B，完成领取流程

### 优点
- ✅ 完全真实的用户体验
- ✅ 可以测试真实的扫码、长按识别等功能
- ✅ 可以测试真实的微信登录流程
- ✅ 可以测试真实的分享功能

### 缺点
- ❌ 需要两部手机
- ❌ 需要两个不同的微信账号

## 附录B：微信开发者工具多账号测试（去重整合版）

### 方法一：使用真机调试（推荐）
1. 手机A 登录账号A（购买购物卡）
2. 手机B 登录账号B（领取购物卡）
3. 开发者工具点击“预览” → “真机调试”
4. 手机A完成购买与分享
5. 手机B扫码/识别二维码完成领取

### 方法二：开发者工具模拟器（快速测试）
1. 清缓存 → 清除数据缓存
2. 账号A完成分享，保存二维码
3. 切换到账号B，输入分享 token 或二维码

### 方法三：测试账号快速切换（开发阶段）
- 仅在开发环境提供测试账号切换入口
- 使用两个窗口分别登录账号A/B，完成分享与领取

### 方法四：开发者工具 + 真机预览组合（最佳实践）
1. 开发阶段使用模拟器
2. 联调阶段使用真机预览
3. 完整测试阶段使用两部手机

### 常见问题
- **清除登录状态**：工具栏“清缓存” → “清除数据缓存”，或调用 `Taro.clearStorage()`
- **查看真机日志**：进入“真机调试”查看控制台
- **获取二维码URL**：分享结果页控制台查看 `qr_image_url`

### 注意事项
1. 真机调试需保持网络可用
2. 分享 token 有效期为 7 天
3. 切换账号前需清除缓存，避免数据混淆
4. 真机调试需在微信后台配置 API 域名

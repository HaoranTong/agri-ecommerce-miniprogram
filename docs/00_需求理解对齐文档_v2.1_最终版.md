## 🎯 一、积分管理模块功能需求理解

### 1.1 积分是什么？
积分是用户通过消费、完成任务等行为获得的虚拟货币，可以：
- **抵扣订单金额**：在下单时使用积分抵扣部分费用（仅支持后台设置的可抵扣商品）
- **兑换商品**：在积分商城兑换指定商品（只显示支持积分兑换的商品）
- **有有效期**：根据后台设置，积分会在一定时间后过期

### 1.2 后台积分规则配置（根据截图理解）

#### 积分获取规则
- **消费积分比例**：每消费¥1 = 1积分（可配置）
- **最低消费金额**：订单金额低于此值不发放积分（0表示不限制）
- **注册赠送积分**：新用户注册时赠送（示例：100积分）
- **每日签到积分**：用户每日签到可获得（示例：10积分）

#### 积分使用规则
- **积分抵扣比例**：每50积分 = ¥1（可配置）
- **最低使用积分**：用户账户积分少于此值时不能使用积分抵扣（示例：50积分）
- **最大抵扣比例**：积分最多可抵扣订单金额的百分比（示例：50%表示最多抵扣50%）
- **最低订单金额**：订单金额低于此值不能使用积分抵扣（0表示不限制）

#### 积分有效期
- **启用积分过期**：可开启/关闭
- **有效期天数**：积分获得后多少天过期（示例：365天，0表示永久有效）

> **重要**：前端所有积分规则的展示内容，必须从后台获取这些配置字段，以后台设置为准。

   - 如果是变体商品，必须在变体列表页面展示
   - 展示商品价格、所需积分等信息
   - 用户选择商品后，进入订单创建页面

3. **订单创建页面**（页面路径见小程序规范）：
   - 展示用户积分余额（积分余额接口见 API 契约）
   - **默认自动填入可以使用的最大的积分数量**
   - 计算逻辑：
     - 从后台获取规则：最大抵扣比例（如50%）、积分抵扣比例（如50积分=1元）
     - 用户选购的商品价格100元
     - 最大可抵扣金额 = 100元 × 50% = 50元
     - 默认填入积分 = 50元 ÷ 抵扣比例（50积分=1元）= 2500积分
     - 如果用户积分余额只有2000积分，则默认填入2000积分
     - 实收金额自动计算 = 100 - (2000 ÷ 50) = 100 - 40 = 60元
   - 用户可以自己修改积分数量
     - 例如：改为用30积分，金额自动变为70元（需要按比例换算）
   - **积分不足时的处理**：
     - 如果用户积分余额不足，比如只有20积分
     - 默认全部积分抵扣，自动填入20积分
     - 自动计算应收金额（根据抵扣比例换算）
     - 提示用户积分不足

4. **提交订单**：
   - 点击提交订单，携带 `points_to_use` 参数
   - 跳转支付页面

5. **前端校验要求**：
   - **积分不足要在前端校验**
   - 直接自动填入可用的全部积分
   - 同时自动调整应付现金

### 2.2 购物卡的三种类型

#### ① 储值购物卡（`fixed_amount` / `stored_value`）
**功能描述**：
- 用户购买指定金额的卡片
- **关键变化**：
  - ✅ **支持任意金额的储值卡购买**
  - ✅ **保持一个通用的储值购物卡模板**（便于用户选择，保持流程的一致和顺畅）
  - ❌ **取消固定面额配置**：不需要后台配置多个固定金额的模板
- 购买后获得卡号，直接绑定购卡用户（当前登录的用户），并保存到购物卡中心
- 使用时，在支付页面选择使用储值购物卡支付商品价款
- 只要验证卡号与登录下单用户一致，就可以完成支付（不需要PIN码）

**购买流程**：
1. 用户在购物卡中心点击"购买购物卡"
2. 跳转到购物卡模板选择页面
3. 选择"储值购物卡"（通用的一个模板）
4. 弹出购买页面，**只需要输入金额**（任意金额）
5. 付款后即可生成购物卡卡号
6. 直接绑定购卡用户，保存到购物卡中心

**使用流程**（重要变化）：
1. 用户在**订单支付页面**（`/pages/order/payment`）
2. 点击"使用储值购物卡"按钮
3. 弹出用户储值购物卡列表
4. 用户选择一张购物卡
5. 系统验证卡号与登录下单用户一致
6. 自动扣减购物卡余额
7. 显示使用情况（使用金额、剩余金额、最终应付金额）
8. 完成支付（如果购物卡余额足够，订单金额为0）

> **关键变化**：储值购物卡的使用不在订单创建页面，而是在**支付页面**（`/pages/order/payment`），与优惠券一起使用。

---

#### ② 固定组合购物卡（`product_bundle` / `bundle`）
**功能描述**：
- 运营预先配置好的商品组合（如：5kg大米 + 2kg小米）
- 用户在购物卡模板选择页面选择"固定组合购物卡"
- 跳转到专门的固定组合购物卡页面，展示后台配置好的各种固定组合产品
- 用户选择下单即可
- 购买成功后同样保存到用户的购物卡中心

**购买流程**：
1. 用户在购物卡中心点击"购买购物卡"
2. 跳转到购物卡模板选择页面
3. 选择"固定组合购物卡"
4. 跳转到固定组合购物卡页面，展示后台配置的各种固定组合产品
5. 用户选择下单
6. 购买成功后保存到购物卡中心

---

#### ③ 任意组合购物卡（`custom_bundle` / `custom`）
**功能描述**：
- 用户可以在商品范围内自由选择商品和数量
- 用户在购物卡模板选择页面选择"任意组合购物卡"
- 直接跳转到正常的购物页面
- 用户按照正常购买商品的流程选择商品并下单
- 在订单详情增加"购物卡"选项，此时自动默认勾选
- 提示用户不需要填写地址
- 购买成功后去购物卡中心查看购物卡明细
- 后续继续走正常支付流程

**购买流程**：
1. 用户在购物卡中心点击"购买购物卡"
2. 跳转到购物卡模板选择页面
3. 选择"任意组合购物卡"
4. 直接跳转到正常的购物页面（首页）
5. 用户按正常流程选择商品并下单
6. 在订单详情页，"购物卡"选项自动默认勾选
7. 提示：不需要填写地址，购买成功后去购物卡中心查看
8. 提交订单，支付
9. **支付成功后，后台自动生成购物卡**（已测试，需再次确认）
10. 去购物卡中心查看购物卡明细

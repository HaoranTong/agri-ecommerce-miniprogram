# 👥 角色权限矩阵（V1.0 - 冻结基线）

## `MyShop 无头电商系统 · agri-ecommerce`

> **适用阶段**：项目一期（人工审核订单 + 分销裂变基础版）
> **目标**：明确各用户角色可访问的 API 资源与操作权限，防止越权、保障数据隔离
> **原则**：最小权限、显式声明、与 WooCommerce 用户角色对齐

------

## 一、角色定义

| 角色                       | 对应 WordPress 角色            | 说明                                                  |
| -------------------------- | ------------------------------ | ----------------------------------------------------- |
| **访客（Guest）**          | 未登录用户                     | 仅浏览商品，无法下单或查看个人数据                    |
| **普通买家（Customer）**   | `customer`                     | 已通过微信登录的用户，可下单、上传凭证、查看订单      |
| **分销推广人（Referrer）** | `customer`（带 referral_code） | 普通买家 + 可生成推广码、查看下级与佣金               |
| **代理商（Agent）**        | `shop_manager`（二期预留）     | 一期不启用，接口预留，权限高于普通用户                |
| **运营管理员（Admin）**    | `administrator`                | 后台人工审核订单、管理商品，**不通过小程序 API 操作** |

> ✅ 一期实际活跃角色：**访客**、**普通买家**、**分销推广人**

------

## 二、API 权限矩阵

> ✅ 表示允许访问；❌ 表示拒绝（返回 401/403）；— 表示无需认证

| API 路径                       | 方法 | 访客 | 普通买家 | 分销推广人 | 代理商 | 说明                         |
| ------------------------------ | ---- | ---- | -------- | ---------- | ------ | ---------------------------- |
| `/auth/login`                  | POST | ✅    | ✅        | ✅          | ✅      | 微信 code 登录               |
| `/products`                    | GET  | ✅    | ✅        | ✅          | ✅      | 商品列表                     |
| `/products/{id}`               | GET  | ✅    | ✅        | ✅          | ✅      | 商品详情                     |
| `/user/profile`                | GET  | ❌    | ✅        | ✅          | ✅      | 获取当前用户信息             |
| `/orders`                      | POST | ❌    | ✅        | ✅          | ✅      | 创建订单                     |
| `/orders`                      | GET  | ❌    | ✅        | ✅          | ✅      | 查看本人订单列表             |
| `/orders/upload-payment-proof` | POST | ❌    | ✅        | ✅          | ✅      | 上传付款截图                 |
| `/gift-cards/redeem`           | POST | ❌    | ✅        | ✅          | ✅      | 兑换购物卡                   |
| `/gift-cards`                  | GET  | ❌    | ✅        | ✅          | ✅      | 查看本人卡包                 |
| `/referral/code`               | GET  | ❌    | ✅        | ✅          | ✅      | 获取本人推广码（无则生成）   |
| `/referral/downlines`          | GET  | ❌    | —        | ✅          | ✅      | 查看直接下级（仅当有下级时） |
| `/commissions`                 | GET  | ❌    | —        | ✅          | ✅      | 查看佣金明细（仅当有佣金时） |
| `/agent/dashboard`             | GET  | ❌    | ❌        | ❌          | ✅      | 代理商首页（一期返回 403）   |

> ⚠️ **关键规则**：
>
> - 所有 `/user/*`、`/orders/*`、`/gift-cards/*` 接口均强制校验 `user_id = 当前 Token 所属用户`
> - `/referral/downlines` 和 `/commissions` 对普通买家返回空数组或 200+空数据，**不报错**
> - 代理商相关接口一期虽存在，但需显式分配 `shop_manager` 角色才可访问

## 三、数据可见性规则

| 数据类型     | 普通买家可见范围    | 分销推广人额外可见         |
| ------------ | ------------------- | -------------------------- |
| **订单**     | 仅自己创建的订单    | 同左                       |
| **下级用户** | 不可见              | 直接通过其推广码注册的用户 |
| **佣金记录** | 不可见              | 由下级订单产生的佣金明细   |
| **购物卡**   | 仅自己兑换/拥有的卡 | 同左                       |

> 🔒 系统禁止跨用户查询（如 A 用户不能查 B 用户的订单）

------

## 四、认证与授权机制

### 1. **认证方式**

- 使用 JWT Token（由 `/auth/login` 返回）
- Token 存入小程序 `storage`，每次请求携带于 `Authorization: Bearer <token>`

### 2. **权限校验逻辑（后端）**

```php
// 示例：检查是否为本人订单
function check_order_owner($order_id, $current_user_id) {
    $order = wc_get_order($order_id);
    if (!$order || $order->get_customer_id() != $current_user_id) {
        wp_send_json_error(['message' => '无权访问'], 403);
    }
}
```

### 3. **分销身份判定**

- 用户首次登录时，若 URL 带 `?ref=ABC123`，则记录 `referral_code = ABC123`
- 若用户自身有 `my_referral_code` 字段，则视为“分销推广人”

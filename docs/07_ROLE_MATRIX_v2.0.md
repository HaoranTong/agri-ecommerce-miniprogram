# 👥 角色权限矩阵（V2.0）

## `MyShop 无头电商 · agri-ecommerce`

> **版本**：V2.0（与《功能规格及技术架构说明书》V1.0、《API 接口契约》V2.3 对齐）
> **适用阶段**：二期（虚拟购物卡、积分中心、代理商仪表盘全面上线）
> **目标**：明确定义各类用户可访问的数据域与 API 操作，建立“最小权限 + 可审计”基线

------

## 一、角色定义与识别

| 角色                         | WordPress 基础角色    | 身份判定标记                                                                  | 主要职责与能力                                     |
| ---------------------------- | --------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------- |
| **访客（Guest）**            | 未登录                 | 无 Token                                                                      | 浏览公开内容，承接邀请或购物卡领取入口             |
| **认证买家（Customer）**     | `customer`             | 成功登录（JWT Token）                                                         | 下单、申请退货、查看个人资产（订单/购物卡/积分）   |
| **分销推广人（Referrer）**   | `customer`             | `usermeta.myshop_referral_code` 存在                                          | 拥有邀请码，查看邀请数据与佣金明细                 |
| **购物卡持有人（Card Owner）** | `customer`             | `wp_myshop_gift_cards.purchaser_id` 或 `redeemer_id` 关联当前用户              | 管理购物卡、赠礼、领取                             |
| **代理商（Agent）**          | `shop_manager`         | `wp_myshop_agents` 存在记录且 `status=active`、`is_active=1`                    | 查看团队指标、下级代理、佣金、渠道素材             |
| **运营管理员（Admin）**      | `administrator`        | 后台帐号；小程序不暴露 Token                                                  | 配置商品/活动、审核订单、人工处理交易              |

> ✅ 认证买家可同时具备推广人、持卡人或代理商身份；权限取并集并以最小授权策略计算。


## 二、API 权限矩阵

> ✅ 允许；❌ 拒绝（HTTP 401/403）；— 无需认证 / 不适用

| 模块 | 操作（接口路径见 API 契约） | 访客 | 认证买家 | 分销推广人 | 购物卡持有人 | 代理商 | 说明 |
| ---- | -------------------------- | ---- | -------- | ---------- | ------------ | ------ | ---- |
| 认证 | 登录 | ✅ | ✅ | ✅ | ✅ | ✅ | 微信 code 换取 JWT |
| 公共配置 | 获取公共配置 | ✅ | ✅ | ✅ | ✅ | ✅ | 首页运营位、公共配置 |
| 邀请追踪 | 渠道追踪 | ✅ | ✅ | ✅ | ✅ | ✅ | 记录渠道参数；访客也可写入 |
| 邀请总览 | 邀请总览 | ❌ | ✅ | ✅ | ✅ | ✅ | 普通买家返回个人数据；访客 401 |
| 商品 | 商品列表/详情 | ✅ | ✅ | ✅ | ✅ | ✅ | 对所有用户开放 |
| 购物车 | 购物车读写 | ❌ | ✅ | ✅ | ✅ | ✅ | 认证后才能操作 |
| 订单 | 创建/列表/详情/退货 | ❌ | ✅ | ✅ | ✅ | ✅ | 仅返回本人订单 |
| 购物卡 | 卡包/分享/领取/核销 | ❌ | ✅ | ✅ | ✅ | ✅ | 仅本人可操作；后端校验归属 |
| 积分 | 总览/流水/兑换 | ❌ | ✅ | ✅ | ✅ | ✅ | 仅本人可见 |
| 分销 | 下级列表/佣金流水 | ❌ | ❌ | ✅ | ✅ | ✅ | 非推广人返回空或受限数据 |
| 代理 | 资料/团队/佣金 | ❌ | ❌ | ❌ | ❌ | ✅ | 仅代理可见 |
| 渠道素材 | 海报素材 | ✅ | ✅ | ✅ | ✅ | ✅ | 接口公开，按需携带邀请参数 |
| 数据看板 | 渠道分析 | ❌ | ❌ | ❌ | ❌ | ❌ | 仅后台运营管理员可见 |

> ⚠️ 说明：
> 1. “—” 表示角色本身不具备该身份，因此无调用场景（例如普通买家不是购物卡持有人时无法重置 PIN）。
> 2. 所有购物卡/积分/订单相关接口均做“数据归属 + 状态”双重校验，拒绝跨用户访问。
> 3. 访客访问需要登录的接口时统一返回 401，前端弹出登录引导；代理商未审批前访问代理接口返回 403。


## 三、数据可见性与隔离策略

| 数据域           | 认证买家默认范围                                   | 分销推广人/购物卡持有人扩展                           | 代理商扩展                                   |
| ---------------- | -------------------------------------------------- | ------------------------------------------------------ | -------------------------------------------- |
| 订单（含退货）   | 仅本人订单；退货信息随订单返回                      | 同上                                                  | 同上                                         |
| 购物卡资产       | 购卡人：订单关联卡；受赠人：已领取卡；共享日志仅本人 | 可额外查看分享口令状态、核销日志                      | 无额外权限                                   |
| 积分流水         | 仅本人明细，分页查询，数据导出需后台操作            | 同上                                                  | 同上                                         |
| 推广大数据       | —                                                  | 查看直接/间接邀请数据（隐藏手机号，展示脱敏昵称）     | 可查看团队下所有邀请数据（脱敏处理）         |
| 佣金报表         | —                                                  | 自身推广佣金、提现记录                                | 自身 + 团队佣金走势（成员信息脱敏）          |
| 代理仪表盘指标   | —                                                  | —                                                      | 可见团队 GMV、活跃代理数、任务完成率         |

> 🔒 任何跨用户检索必须在数据库层面添加 `WHERE owner_id = current_user_id` 或授权校验，禁止在前端过滤。


## 四、授权校验流程

1. **统一认证**：所有受保护接口使用 JWT；Token 失效时后端返回 401，前端清除本地缓存并跳转登录。
2. **角色识别**：
     - 分销人：`myshop_referral_code` 存在且 `referral_status = active`。
     - 购物卡持有人：卡记录中的 `purchaser_id` / `redeemer_id` 匹配当前用户。
    - 代理商：`wp_myshop_agents` 存在记录且状态有效，未通过审核返回 403。
3. **领域校验示例**：
     - 购物卡分享仅允许购卡人操作；非购卡人返回权限错误（401/403 以 API 契约为准）。
     - 代理下级列表仅允许代理身份访问；非代理返回权限错误（401/403 以 API 契约为准）。

4. **分享口令安全**：
    - 分享接口生成一次性口令，写入分享审计日志；成功领取或撤销后立即失效。
    - 领取接口必须登录，成功后记录领取人。
5. **积分预占**：积分兑换接口执行时检查用户积分余额 & 预占状态，失败次数达到策略阈值触发风控提醒。


## 五、审计与风控

    - 购物卡：分享、领取、核销记录于 `wp_myshop_gift_card_share_logs` / `wp_myshop_gift_card_redemptions`。
    - 代理商：变更等级、冻结账号写入 `wp_myshop_agent_audit_logs`。
        - 连续 3 次积分兑换失败 → 返回错误码（见 API 契约），前端提示联系人工客服。
    - 礼品卡口令输入错误超阈值 → 锁定卡片（状态值以 API 契约为准），需走客服解锁流程。

#### Bug修复
- ✅ 修复积分规则API 404错误
  - 文件：`api/points-controller.php`
  - 添加 `GET /points/rules` 端点
  - 目前返回空数组，后续可扩展

- ✅ 修复积分扣除未核销问题
  - 文件：`api/order-controller.php`
  - 问题：订单完成后，积分抵扣的积分没有被扣除
  - 原因：积分扣除是在订单状态变为 `processing` 时触发，但订单可能跳过该状态
  - 修复：在订单创建时立即扣除积分（在订单保存后立即调用 `deduct_points_for_order`）
  - 逻辑：如果使用了积分抵扣，在订单创建时立即扣除，不再等待订单状态变为 processing

- ✅ 优化默认地址自动填充
  - 文件：`api/user-controller.php`、`src/pages/order/create.tsx`、`src/services/api.ts`
  - 添加获取用户地址列表API：`GET /user/addresses`
  - 返回用户的地址列表和默认地址
  - 订单创建页面优先从后端获取默认地址，自动填充到表单
  - 用户可以在此基础上修改地址信息

- ✅ 修复积分抵扣页面显示和输入问题
  - 文件：`src/pages/order/create.tsx`、`src/pages/order/create.scss`
  - 问题：
    - 无论实际支付多少积分，都显示"使用全部"，没有显示实际可用的最大积分数量
    - 输入框不能输入数字，删除和输入都不接受，任何数据都不能输入
    - 抵扣金额不显示
    - 清除按钮点击后变成提示，无法正常使用
  - 修复：
    - 移除"使用全部"和"清除"按钮
    - 页面加载时自动填入最大可用积分数量（根据订单总额和积分规则计算）
    - 如果用户积分余额不足最高可抵扣金额，自动填入全部积分余额（通过 `Math.min(availablePoints, maxPointsByOrder)` 实现）
    - **重构输入处理逻辑**：允许用户自由输入、删除和修改积分数量，输入过程中不限制，只在失去焦点时进行验证和调整
    - **优化自动填入逻辑**：只在首次加载时自动填入一次，之后不再自动覆盖用户输入
    - **添加失去焦点验证**：用户输入完成后，在失去焦点时进行验证，超出限制时自动调整并提示
    - 抵扣金额实时显示并动态计算（随输入的积分数量变化）
    - 添加提示文本："最多可使用 X 积分（可修改）"
    - 输入验证：仅在超出限制时自动调整，允许用户自由输入过程中的中间状态

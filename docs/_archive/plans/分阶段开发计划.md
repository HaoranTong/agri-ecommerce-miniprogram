
农产品电商小程序 · 分阶段开发计划（V2.0）

我们已经完成了**文档基线**同步（功能规格 V1.0、API 契约 V2.3、数据模型 V2.1、角色矩阵 V2.0、工程规范 V2.0 等），可以在保持文档一致性的前提下开展开发工作。

以下计划覆盖 **一期 MVP**（人工收款）与 **二期扩展**（虚拟购物卡分享/领取、积分中心、代理仪表盘），采用“后端优先、前端对齐、双向验收”的节奏推进。

------

## 🧭 阶段目标总览

- **一期（MVP）**：2 周内交付“微信登录 → 浏览 → 下单 → 上传付款凭证 → 查看订单”闭环。
- **二期（营销拉新）**：3-4 周内上线虚拟购物卡分享/领取、积分中心、分销佣金、代理商仪表盘，并保证与文档同步。
- **持续目标**：所有代码改动需通过文档→接口→前端三方校验，确保字段“只增不改”。

## 🔄 协作与验收方式

1. **需求变更**：先修改文档 → Review → 执行开发 → 文档留痕。
2. **接口联调**：开发阶段使用 Postman 集合 `docs/postman/myshop-api-test-suite.postman_collection.json`。
3. **验收判定**：
   - 后端：接口返回结构与 API 契约一致；数据库写入符合数据模型；角色权限校验通过。
   - 前端：页面功能与 MINIPROGRAM_SPEC V2.0 一致；错误码映射到中文提示。
4. **回归测试**：Step 5、Step 10 使用 checklist（后续补充）执行回归。

### 二期功能规划（Phase 4：营销组合与优惠套装）

**H. 优惠组合套装**（待实现，已记录需求）
**业务场景**：支持跨规格组合优惠销售，如"袋装10kg普通种植稻花香 + 2kg体验装有机稻花香"

**功能需求**：
- [ ] 后端支持组合商品配置（Bundle Product）
  - [ ] 定义组合商品表 `wp_myshop_bundles`（包含 bundle_id、name、description、price、discount_type）
  - [ ] 定义组合明细表 `wp_myshop_bundle_items`（关联 variation_id、quantity）
  - [ ] API 接口 `/products/bundles`（返回所有组合套餐）
  - [ ] API 接口 `/products/bundles/{id}`（组合详情）
  
- [ ] 前端展示组合商品
  - [ ] 在首页/商品列表显示组合商品卡片（带"优惠套装"标签）
  - [ ] 创建 `pages/product/bundle`：组合商品详情页（展示包含的所有商品、价格对比）
  - [ ] 支持将整个组合加入购物车（作为一个 line_item）
  
- [ ] 购物车与订单支持
  - [ ] 购物车显示组合商品（展开显示内部商品）
  - [ ] 订单结算时正确计算组合价格
  - [ ] 订单详情展示组合商品明细

**技术要点**：
- 组合商品价格可以是固定价或折扣百分比（如"原价 ¥200，组合价 ¥180"）
- 库存检查需要验证所有子商品库存
- 支持部分退款（退组合商品需要特殊处理）

**优先级**：低（二期功能）
**预计工期**：5-7天（后端 3天 + 前端 2天 + 联调 2天）

## 一、项目概述

### 1.1 产品定位

安家大米是一个以"高品质农产品"为核心的微信小程序电商系统，采用"内容种草 → 社交裂变 → 小程序成交 → 私域复购"的商业模式。

### 1.2 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│                      微信小程序前端 (Taro React)              │
├─────────────────────────────────────────────────────────────┤
│                      HTTPS REST API                          │
├────────────────────────┬────────────────────────────────────┤
│   WordPress + WooCommerce │         自定义插件 (myshop-core) │
├────────────────────────┴────────────────────────────────────┤
│                        MySQL 数据库                          │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 核心技术栈

| 层级 | 技术/工具 | 版本要求 | 说明 |
|------|-----------|----------|------|
| 前端 | Taro + React | ≥ 4.1 | 编译为微信小程序 |
| 前端 | TypeScript | ≥ 5.4 | 强类型约束 |
| 后端 | WordPress | ≥ 6.5 | CMS + 用户体系 |
| 电商引擎 | WooCommerce | ≥ 8.0 | 电商核心功能 |
| 数据库 | MySQL | ≥ 5.7 | 存储层 |
| 认证 | JWT | 最新版 | Token 认证 |

## 三、用户体系模块

### 3.1 功能描述

用户体系是整个小程序的基础，提供微信授权登录、用户资料管理和身份认证功能。

### 3.2 核心功能

#### 3.2.1 微信授权登录

- **接口**: `POST /auth/login`
- **流程**: 微信 code → 换取 JWT token → 返回用户信息
- **数据存储**: `wp_usermeta` 存储 `openid`、`phone`、`invite_code` 等字段

#### 3.2.2 用户资料管理

- **查看资料**: `GET /user/profile`
- **修改资料**: `PUT /user/profile`
  - 可修改字段: `nickname`、`first_name`、`phone`
  - 手机号按中国大陆 11 位规则校验

### 3.3 页面清单

| 页面路径 | 文件 | 功能描述 |
|----------|------|----------|
| `/pages/auth/login` | `login.tsx` | 微信授权登录页 |
| `/pages/user/profile` | `profile.tsx` | 用户中心首页 |
| `/pages/user/edit-profile` | `edit-profile.tsx` | 编辑个人资料 |

### 3.4 用户数据字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `user_id` | number | WordPress 用户 ID |
| `nickname` | string | 用户昵称 |
| `first_name` | string | 真实姓名 |
| `phone` | string | 手机号 |
| `avatar` | string | 头像 URL |
| `openid` | string | 微信 OpenID |
| `invite_code` | string | 邀请码 |
| `referrer_id` | number | 推荐人 ID |
| `points_balance` | number | 积分余额 |
| `is_agent` | boolean | 是否代理商 |
| `agent_code` | string | 代理商代码 |

## 六、订单系统模块

### 6.1 功能描述

订单系统负责订单的创建、支付、查看和管理，是交易的核心环节。

### 6.2 核心功能

#### 6.2.1 创建订单

- **接口**: `POST /orders`
- **参数**:
  - `variation_id`: 变体 ID
  - `quantity`: 数量
  - `points_to_use`: 使用的积分数量
  - `shipping_address`: 收货地址
- **返回**: 订单信息 + 支付指引

#### 6.2.2 订单列表

- **接口**: `GET /orders`
- **返回**: 订单列表（包含状态、金额、创建时间）

#### 6.2.3 订单详情

- **接口**: `GET /orders/{order_id}`
- **返回**: 完整订单信息（商品列表、地址、支付状态）

#### 6.2.4 支付流程

1. **展示支付信息**: 收款二维码、客服二维码、支付说明
2. **上传凭证**: `POST /orders/{id}/upload-payment-proof`
   - 支持 jpg/png，最大 5MB
   - 存储到 `/wp-content/uploads/payment-proofs/年/月/`
3. **后台审核**: 管理员查看凭证后更新订单状态

### 6.3 页面清单

| 页面路径 | 文件 | 功能描述 |
|----------|------|----------|
| `/pages/order/create` | `create.tsx` | 创建订单页 |
| `/pages/order/order-confirm` | `order-confirm.tsx` | 订单确认页 |
| `/pages/order/payment` | `payment.tsx` | 支付页 |
| `/pages/order/payment-success` | `payment-success.tsx` | 支付成功页 |
| `/pages/order/detail` | `detail.tsx` | 订单详情页 |
| `/pages/order/list` | `list.tsx` | 订单列表页 |

### 6.4 订单状态流转

```
pending (待支付) 
  ├── 上传支付凭证 → processing (处理中)
  └── 管理员确认 → completed (已完成)
```

## 八、积分系统模块

### 8.1 功能描述

积分系统是用户激励体系的核心，包含积分获取、积分消费、积分规则和任务中心。

### 8.2 核心功能

#### 8.2.1 积分余额

- **接口**: `GET /points/balance`
- **返回字段**:
  - `available`: 可用积分
  - `pending`: 待入账积分
  - `frozen`: 冻结积分
  - `expiring_soon`: 即将过期积分
  - `expiring_date`: 过期日期

#### 8.2.2 积分流水

- **接口**: `GET /points/ledger`
- **查询参数**:
  - `page` / `per_page`: 分页
  - `type`: earn/spend/expire/refund
  - `status`: pending/confirmed
  - `from` / `to`: 日期范围

#### 8.2.3 积分抵扣

- **订单中使用积分**: `POST /orders` 携带 `points_to_use`
- **计算逻辑**:
  ```
  可抵扣金额 = 积分数量 ÷ 抵扣比例
  最大抵扣金额 = 订单金额 × 最大抵扣比例
  ```

#### 8.2.4 积分规则

- **接口**: `GET /points/rules`
- **规则类型**:
  - 下单返积分（每消费1元获得X积分）
  - 邀请好友奖励
  - 每日签到
  - 完善资料奖励

#### 8.2.5 任务中心

- **获取任务**: `GET /points/missions`
- **领取奖励**: `POST /points/missions/{mission_id}/claim`
- **任务类型**:
  - 完善个人资料
  - 完成首单
  - 每日签到
  - 邀请好友

#### 8.2.6 积分兑换

- **获取兑换选项**: `GET /points/redeem/options`
- **执行兑换**: `POST /points/redeem`
- **兑换类型**:
  - 优惠券
  - 礼品卡
  - 实物商品

## 九、购物卡系统模块

### 9.1 功能描述

购物卡系统提供虚拟购物卡的购买、分享、领取和兑换功能，支持三种类型：储值卡、固定组合卡、任意组合卡。

### 9.2 购物卡类型

#### 9.2.1 储值购物卡 (fixed_amount)

- **特点**: 固定金额，可多次使用
- **购买**: 任意金额输入
- **使用**: 在支付页面抵扣订单金额
- **余额**: 支持部分抵扣，余额可保留

#### 9.2.2 固定组合购物卡 (product_bundle)

- **特点**: 后台预设的商品组合
- **购买**: 选择预设组合下单
- **使用**: 兑换对应商品组合

#### 9.2.3 任意组合购物卡 (custom_bundle)

- **特点**: 用户自由选择商品
- **购买**: 正常购物流程，勾选"转为购物卡"
- **使用**: 兑换选择的商品

### 9.3 核心功能

#### 9.3.1 购物卡中心

- **入口**: "我的"页面 → "购物卡"
- **功能**:
  - 查看所有购物卡
  - 购买购物卡
  - 兑换商品
  - 分享/赠送
  - 管理购物卡

#### 9.3.2 购买流程

1. 选择购物卡类型
2. 选择模板（储值卡为通用模板）
3. 输入金额（储值卡）或选择组合
4. 提交订单
5. 支付成功后自动生成购物卡

#### 9.3.3 分享功能

- **接口**: `POST /gift-cards/share`
- **功能**:
  - 选择分享样式模板
  - 编辑祝福语（可选）
  - 生成二维码
  - 下载 PDF（打印版）
- **分享样式**: 从后台配置获取，支持多种模板

#### 9.3.4 领取流程

1. 受赠人扫描二维码
2. 跳转登录页面
3. 显示领取提示
4. 确认后绑定到账户
5. 跳转"我的"页面

#### 9.3.5 兑换商品

- **接口**: `POST /gift-cards/redeem`
- **流程**:
  1. 选择要兑换的购物卡
  2. 填写收货地址
  3. 生成 0 元订单
  4. 等待发货

#### 9.3.6 支付页面使用

- **优惠券**: 输入优惠券码，验证后抵扣
- **储值购物卡**: 选择可用储值卡，自动抵扣

优惠券系统使用 WooCommerce 原生优惠券功能，支持在支付页面输入优惠券码抵扣。

### 10.2 核心功能

#### 10.2.1 验证优惠券

- **接口**: `POST /coupons/validate`
- **参数**: `code` - 优惠券码
- **返回**: 优惠券信息（类型、金额、描述）

#### 10.2.2 应用优惠券

- **接口**: `POST /orders/{order_id}/apply-coupon`
- **参数**: `coupon_code`
- **返回**: 抵扣后的订单金额

### 10.3 使用位置

- **支付页面**: `/pages/order/payment`
- **使用方式**: 点击"使用优惠券"，输入优惠券码

  - `region_province`: 省份
  - `region_city`: 城市
  - `level`: 代理等级
  - `parent_agent_code`: 上级代理

#### 12.2.2 代理资料

  - 佣金统计（待发、已发、可用）
  - 团队统计

#### 12.2.3 下级代理

- **接口**: `GET /agents/downlines`
- **返回**: 下级代理列表

#### 12.2.4 代理佣金

| `share_token_invalid` | 410 | 分享链接失效 |
| `not_authorized_agent` | 403 | 无代理商权限 |
| `region_occupied` | 409 | 区域已被占用 |

### 17.2 状态枚举

| 状态 | 适用模块 | 说明 |
|------|----------|------|
| `pending` | 订单/佣金 | 待处理 |
| `processing` | 订单 | 处理中 |
| `completed` | 订单 | 已完成 |
| `cancelled` | 订单 | 已取消 |
| `approved` | 佣金 | 已审核 |
| `paid` | 佣金 | 已发放 |
| `active` | 购物卡/代理 | 有效 |
| `redeemed` | 购物卡 | 已兑换 |
| `expired` | 购物卡/积分 | 已过期 |
| `frozen` | 代理 | 已冻结 |

## 3. 商品管理

### 3.1 添加新商品
1. 进入 **WooCommerce → 商品**
2. 点击 **添加商品**
3. 填写商品信息：
   - **商品名称**: 如"有机大米"
   - **商品描述**: 详细介绍
   - **商品数据**: 选择"可变商品"（如有规格）
   - **价格**: 设置销售价格
   - **库存**: 管理库存数量
   - **图片**: 上传商品图片

### 3.2 添加商品变体（规格）
1. 在商品编辑页面，选择 **商品数据 → 可变商品**
2. 点击 **属性** 标签：
   - 添加属性（如：包装、品质、重量）
   - 勾选 **用于变体**
   - 保存属性
3. 点击 **变体** 标签：
   - 点击 **从所有属性创建变体**
   - 为每个变体设置价格和库存

### 3.3 商品分类
1. 进入 **商品 → 分类**
2. 添加分类（如：大米、蔬菜、水果）
3. 在商品编辑页面选择分类

### 3.4 商品上下架
- **上架**: 点击商品编辑 → 状态设为"已发布"
- **下架**: 状态设为"草稿"或"私有"
- **批量操作**: 在商品列表勾选商品 → 批量操作 → 编辑 → 状态

- 退款成功后：订单状态变为 **已退款**

## 7. 积分系统管理

> ⚠️ **新功能** - 2025-11-26 上线

### 7.1 功能说明
完整的用户积分体系，支持消费获得积分、积分抵扣订单、注册赠送、每日签到等功能。

### 7.2 积分设置

#### 访问设置页面
1. 进入 **💰 积分管理 → 积分设置**
2. 配置积分获取和使用规则

#### 🎁 积分获取规则

**启用积分系统**
- 勾选此项开启积分功能
- 关闭后用户无法获得和使用积分

**消费积分比例**
- 设置用户消费金额转换为积分的比例
- 例如：设置为 `10`，用户消费 ¥100 可获得 1000 积分
- 建议设置：5-20 之间

**最低消费金额**
- 订单金额低于此值不发放积分
- 设置为 `0` 表示不限制
- 用途：避免小额订单频繁发放积分

**注册赠送积分**
- 新用户注册时自动赠送的积分
- 建议设置：50-200 积分
- 用途：吸引新用户首次购物

**每日签到积分**
- 用户每日签到可获得的积分
- 设置为 `0` 表示禁用签到功能
- 建议设置：5-20 积分

#### 🛒 积分使用规则

**允许积分抵扣**
- 开启后用户下单时可使用积分抵扣金额
- 关闭后积分仅作为奖励积累

> ✅ 说明：
> - **积分抵扣** 仅由此处规则控制，与「积分兑换商品」无关。
> - **积分兑换商品** 是“积分换购商品”的独立功能（在对应菜单配置可兑换的商品/变体）。
> - **积分兑换项** 是“积分兑换优惠券/礼品/权益”的独立功能（在积分兑换项菜单配置）。
> 三者互不冲突，可同时启用。

**积分抵扣比例**
- 设置多少积分可抵扣 ¥1
- 例如：设置为 `100`，100 积分 = ¥1
- 建议设置：50-200 之间

**最低使用积分**
- 用户积分少于此值时不能使用
- 例如：设置为 `100`，用户至少需要 100 积分才能使用
- 建议设置：50-200 积分

**最大抵扣比例**
- 积分最多可抵扣订单金额的百分比
- 例如：设置为 `50`，订单 ¥100 最多抵扣 ¥50
- 建议设置：20-70%
- 用途：保证商家利润，避免全额抵扣

**最低订单金额**
- 订单金额低于此值不能使用积分
- 设置为 `0` 表示不限制
- 建议设置：¥50-100

#### ⏰ 积分有效期

**启用积分过期**
- 开启后积分将在指定时间后过期
- 用途：促进用户活跃度

**有效期天数**
- 积分获得后多少天过期
- 设置为 `0` 表示永久有效
- 建议设置：180-365 天

### 7.3 积分设置示例

#### 示例一：促销型（激进）
```
消费积分比例: 20 (消费 ¥1 = 20 积分)
积分抵扣比例: 50 (50 积分 = ¥1)
最大抵扣比例: 70%
注册赠送: 200 积分 (= ¥4)
```
**效果**: 高积分回馈，用户消费 ¥100 得 2000 积分，下次可抵扣 ¥40

#### 示例二：平衡型（推荐）
```
消费积分比例: 10 (消费 ¥1 = 10 积分)
积分抵扣比例: 100 (100 积分 = ¥1)
最大抵扣比例: 50%
注册赠送: 100 积分 (= ¥1)
```
**效果**: 适中回馈，用户消费 ¥100 得 1000 积分，下次可抵扣 ¥10

#### 示例三:保守型（稳健）
```
消费积分比例: 5 (消费 ¥1 = 5 积分)
积分抵扣比例: 200 (200 积分 = ¥1)
最大抵扣比例: 30%
注册赠送: 50 积分 (= ¥0.25)
```
**效果**: 低积分回馈，用户消费 ¥100 得 500 积分，下次可抵扣 ¥2.5

### 7.5 积分自动化规则

#### 自动发放积分
系统会在以下情况自动发放积分：

**1. 订单完成时**
- 触发条件：订单状态变更为"处理中" / "已发货(运输中)" / "已完成"
- 发放规则：订单金额 × 消费积分比例
- 限制条件：
  - 订单金额需 ≥ 最低消费金额
  - 同一订单只发放一次
  - 积分状态为"已确认"
- 订单备注：自动添加"已发放 XXX 积分"

**2. 用户注册时**
- 触发条件：新用户完成注册
- 发放规则：注册赠送积分（如设置 > 0）
- 积分状态：立即确认
- 用途：鼓励新用户首次购物

**3. 每日签到时**（需小程序端实现）
- 触发条件：用户调用签到API
- 发放规则：每日签到积分（如设置 > 0）
- 限制条件：每日仅能签到一次

#### 自动扣除积分
系统会在以下情况自动扣除积分：

**1. 订单提交时**
- 触发条件：用户下单时选择使用积分
- 扣除规则：
  - 订单金额 × 最大抵扣比例 = 最大可抵扣金额
  - 使用积分 ÷ 积分抵扣比例 = 实际抵扣金额
  - 取两者较小值
- 订单显示：添加"积分抵扣"费用项（负数）

**2. 订单状态变为处理中时**
- 触发条件：订单状态从"待支付"变为"处理中"
- 扣除逻辑：从用户积分余额中扣除
- 积分状态：已确认
- 订单备注：自动添加"已使用 XXX 积分抵扣 ¥XX"

#### 自动退还积分
系统会在以下情况自动退还积分：

**1. 订单取消时**
- 触发条件：订单状态变为"已取消"或"已退款"
- 退还规则：退还订单中使用的所有积分
- 限制条件：同一订单只退还一次
- 订单备注：自动添加"已退还 XXX 积分"

### 7.6 小程序端使用积分

#### 用户查看积分
小程序端可通过积分接口获取积分信息（接口路径与字段以 API 契约为准）。

#### 下单时使用积分
小程序创建订单时传递积分抵扣参数（字段以 API 契约为准）。

系统会自动：
1. 验证积分是否足够
2. 验证是否符合使用规则
3. 计算实际抵扣金额
4. 在订单中添加"积分抵扣"项
5. 订单确认后扣除积分

### 7.7 手动管理积分（高级）

#### 通过API手动发放积分
使用 WP-CLI 或 Postman 调用“积分发放”接口（路径与字段以 API 契约为准），需携带管理员凭证。

#### 通过数据库查询用户积分
```sql
SELECT 
    u.display_name AS 用户名,
    u.user_email AS 邮箱,
    COALESCE(SUM(CASE WHEN p.status = 'confirmed' THEN p.delta ELSE 0 END), 0) AS 可用积分,
    COALESCE(SUM(CASE WHEN p.type = 'earn' THEN p.delta ELSE 0 END), 0) AS 累计获得,
    COALESCE(SUM(CASE WHEN p.type = 'spend' THEN ABS(p.delta) ELSE 0 END), 0) AS 累计消费
FROM wp_users u
LEFT JOIN wp_myshop_point_ledger p ON u.ID = p.user_id
GROUP BY u.ID
ORDER BY 可用积分 DESC
LIMIT 100;
```

### 7.8 积分系统最佳实践

#### 推荐配置
- ✅ 设置合理的积分价值（不要过高或过低）
- ✅ 限制最大抵扣比例（保证利润）
- ✅ 设置积分有效期（促进活跃）
- ✅ 定期举办积分翻倍活动

#### 注意事项
- ⚠️ 积分一旦发放不可撤回（除非订单退款）
- ⚠️ 修改积分规则不影响已有积分
- ⚠️ 积分不能转让给其他用户
- ⚠️ 积分不能兑换现金

#### 运营建议
- 📊 每月查看积分发放/消费统计
- 📈 分析积分对复购率的影响
- 🎁 节假日提高积分赠送比例
- 💰 积分兑换项（已支持配置）

## 8. 测试用户管理（开发环境）

### 8.1 功能概述
测试用户系统用于开发环境中模拟不同的用户登录，确保测试数据的持久性。在微信开发者工具中，每次清除缓存后 `wx.login()` 会生成新的随机 `code`，导致后端创建新的用户，之前的订单、积分、收货地址等数据无法访问。

通过固定的测试用户代码（如 `test001`），可以始终映射到相同的 `openid`，从而保持用户数据的连续性。

> **⚠️ 安全警告**: 此功能仅用于开发环境，生产环境必须禁用！

---

### 8.2 访问测试用户管理
1. 进入 **用户 → 测试用户管理**
2. 页面显示：
   - 预设测试用户列表（4个固定用户）
   - 自定义测试用户管理
   - 使用说明和示例代码

---

### 8.3 预设测试用户

系统预设了 4 个固定测试用户：

| 测试代码 | OpenID | 昵称 | 用途 |
|---------|--------|------|------|
| `test001` | `oTest_User_001_FixedOpenID` | 测试用户001 | 普通用户测试 |
| `test002` | `oTest_User_002_FixedOpenID` | 测试用户002 | 多用户测试 |
| `test003` | `oTest_User_003_FixedOpenID` | 测试用户003 | 边界测试 |
| `admin` | `oTest_Admin_999_FixedOpenID` | 管理员测试账号 | 管理员功能测试 |

**特点**：
- ✅ 代码和 OpenID 永久固定
- ✅ 无法删除，保证始终可用
- ✅ 清除缓存后数据依然存在

### 8.4 添加自定义测试用户

如果需要更多测试账号：

1. 在 **添加新测试用户** 区域填写：
   - **测试代码**: 如 `vip001`（唯一标识符）
   - **固定 OpenID**: 如 `oTest_VIP_001_FixedID`（建议使用有意义的前缀）
   - **昵称**: 如 "VIP会员测试"
2. 点击 **添加测试用户**
3. 新用户会立即显示在列表中

**命名建议**：
- 测试代码: 使用小写字母+数字，如 `test004`, `vip001`, `agent001`
- OpenID: 格式 `oTest_<类型>_<编号>_FixedOpenID`，便于识别

### 8.7 小程序开发中使用测试用户

#### 方法一：手动指定测试代码（推荐）

在登录代码中硬编码测试代码：

```typescript
// src/pages/auth/login.tsx

const handleLogin = async () => {
  try {
    // 开发环境：使用固定测试代码
    const code = process.env.NODE_ENV === 'development' 
      ? 'test001'  // 👈 修改这里切换测试用户
      : (await Taro.login()).code;
    
    await authService.login(code);
    // ... 其他逻辑
  } catch (error) {
    console.error('登录失败', error);
  }
};
```

**优点**：
- 简单直接，无需额外组件
- 代码清晰，易于调试

**缺点**：
- 每次切换用户需要修改代码

---

#### 方法二：使用测试用户选择器（自动集成）

系统已自动集成测试用户选择器组件，在开发环境中会在页面右下角显示 🧪 按钮。

**使用步骤**：
1. 在微信开发者工具中打开小程序
2. 点击右下角的 **🧪** 按钮
3. 在弹出的面板中选择测试用户：
   - 测试用户001 (`test001`)
   - 测试用户002 (`test002`)
   - 测试用户003 (`test003`)
   - 管理员测试账号 (`admin`)
4. 点击选择后，页面会自动刷新并使用所选测试用户登录
5. 点击 **清除选择** 可恢复使用真实微信登录

**技术实现**：
- 选择的测试代码存储在 `Taro.storage` 中（键: `DEV_TEST_USER_CODE`）
- 登录时自动检测存储的测试代码并使用
- 仅在 `NODE_ENV === 'development'` 时显示

**优点**：
- ✅ 可视化操作，无需修改代码
- ✅ 快速切换不同测试用户
- ✅ 生产环境自动隐藏

### 8.10 生产环境安全检查

在部署到生产环境前，务必确认：

- [ ] 测试用户管理页面已隐藏或删除
- [ ] 小程序代码中没有硬编码测试代码
- [ ] 测试用户选择器组件不会在生产环境显示
- [ ] 后端 API 已禁用测试用户映射功能

**建议配置**：

在 `wp-config.php` 中添加环境变量：

```php
// 开发环境
define('WP_ENVIRONMENT_TYPE', 'development');

// 生产环境
define('WP_ENVIRONMENT_TYPE', 'production');
```

在 `class-myshop-auth.php` 中检查环境：

```php
if (wp_get_environment_type() !== 'development') {
    // 生产环境：禁用测试用户映射
    return $this->generate_random_openid($code);
}
```

### 8.11 常见问题

**Q: 清除缓存后为什么还是新用户？**  
A: 检查以下几点：
1. 是否在登录代码中使用了测试代码（如 `test001`）
2. 测试用户选择器是否选择了测试账号
3. 后端是否正确配置了测试用户映射

**Q: 测试用户可以用于生产环境吗？**  
A: ❌ 绝对不可以！测试用户绕过了微信登录验证，存在严重安全风险。

**Q: 如何模拟不同的用户角色？**  
A: 
1. 为不同角色创建不同的测试用户（如 `vip001`, `agent001`）
2. 在后台手动设置这些用户的角色或元数据
3. 在小程序中切换测试账号进行测试

**Q: 测试用户的数据会影响生产数据吗？**  
A: 在同一个数据库中，测试用户的数据与真实用户数据混在一起。建议：
- 开发环境使用独立数据库
- 定期清理测试数据
- 在测试订单中添加明显标识

## 12. 常见问题 FAQ

### 12.1 订单问题

**Q: 用户申请退货后如何处理？**  
A: 进入 WooCommerce → 退货管理，按申请操作“同意/拒绝”，同意会自动退款并更新状态。

**Q: 如何批量发货？**  
A: 在订单列表勾选多个订单 → 批量操作 → 编辑 → 状态改为"已发货/运输中"（需先在每个订单添加快递单号）。

### 12.2 商品问题

**Q: 商品变体价格不显示？**  
A: 检查变体是否已设置价格，且库存状态为"有货"。

**Q: 如何隐藏缺货商品？**  
A: 进入 **WooCommerce → 设置 → 商品 → 库存** → 勾选"缺货时隐藏"。

### 12.3 快递问题

**Q: 添加快递单号后订单状态没变？**  
A: 只有"处理中"状态的订单才会自动变为"已发货/运输中"，其他状态需手动更改。

**Q: 快递公司列表不够用？**  
A: 选择"其他"选项，然后在订单备注中注明具体快递公司。

### 12.4 系统问题

**Q: 后台页面加载慢？**  
A: 
1. 清理数据库冗余数据
2. 启用对象缓存（Redis/Memcached）
3. 升级服务器配置

**Q: 忘记管理员密码？**  
A: 使用 phpMyAdmin 修改 `wp_users` 表中的密码（MD5加密）。
